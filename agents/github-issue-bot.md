## How to use it

Mention **`@claude`** in a new issue or an issue comment, and ask your
question:

> @claude What is our target T2L, and what happens when the CSV import fails?

The bot replies with a comment, usually within a minute or two. It cites the
files it used. If the docs don't have the answer, it says so.

## What it does

1. Triggers on a **new issue** or **new issue comment** that contains
   `@claude`. Pull request comments are ignored.
2. Reads the knowledge base: `docs/`, `runbooks/`, `agents/` and
   `GLOSSARY.md`. Folder `README.md` stubs are skipped.
3. Sends the issue title, body and the new comment, together with the
   knowledge base, to the Claude API.
4. Posts the answer as an issue comment, with a footer saying it was
   generated by Claude.

It answers **only from the docs**: no web access, no other tools, and it can't
change files or open PRs.

## Rules & data handling

> ⛔ **Everything in the issue is sent to Claude.** Never put customer PII,
> payment data, passwords or API keys in an issue that mentions `@claude`.
> This follows the rule that
> [customer data stays in designated systems](../docs/company/mission-values.md#3-customer-data-stays-in-designated-systems).

- The bot is instructed never to output secrets or customer data, and to
  treat issue text as a question, not as instructions.
- Answers can be wrong or out of date. Always check the cited files. If a
  doc is wrong or missing, fix it with a PR (see
  [keeping the brain up to date](../meta/self-updating.md)).
- **Cost:** each answer sends the whole knowledge base (about 32K characters
  today) to the API. Prompt caching reduces repeat costs. Cost grows as the
  docs grow.

## How to turn it off

- **Temporarily:** in GitHub, go to **Actions → Claude issue responder →
  ⋯ → Disable workflow**.
- **Permanently:** delete the workflow file through a PR, and revoke the API
  key.
